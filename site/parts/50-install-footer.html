Install MAG, let it set up known tools, then store one real choice and search for it in different words.

TERMINALmacOS · Linux
$ curl -fsSL https://raw.githubusercontent.com/George-RD/mag/main/install.sh | sh
$ mag ingest "Use exponential backoff with jitter" \
    --tags decision,project:api-gateway
$ mag advanced-search "How should failed requests retry?" --explain
Also available: brew install George-RD/mag/mag npm install -g mag-memory cargo install mag-memory uv tool install mag-memory

Questions worth asking first.

Why not keep everything in project docs?

Keep source-of-truth facts in project docs. MAG is better for context that changes often, spans projects or should follow you between tools. The two approaches work together.

Does any memory data leave my machine?

Not in the default setup. Search runs locally and needs no cloud API. First use downloads the model. API models only run when you set them up.

Is the database encrypted?

No. MAG stores memories in a plaintext SQLite file. Use full-disk encryption and do not store secrets.

Will it remember the right things by itself?

MAG can save and recall context, but memory quality still depends on what is stored. Clear rules for decisions, bug fixes and handoffs produce better results than saving everything.
