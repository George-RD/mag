Demo 01 · Retrieval

One search through
the real pipeline.

This walks a single mag advanced-search call through twelve states. The values shown at each state are the ones MAG wrote into _explain when this exact query ran against this exact database.

$ mag advanced-search "how should retries work?" --explain

Captured 4 September 2026 against a three-memory database. mag 0.1.10-dev, embedding model bge-small-en-v1.5 int8, 384 dimensions. --limit is left at its default of 10, so all three memories fit inside the result set. The binary is built with the default feature set, the same one the release workflow ships: sqlite-vec is opt-in and is not compiled in, so there is no vec_memories table and vector search reads the embedding column of memories directly.

The processed: prefix on every content value is a defect, not a label. The CLI ingest path routes through a compatibility pipeline that prepends it. The tag entity:people:retries is a second defect from the same cause: the entity extractor skips the sentence-initial word, so the prefix pushes a real content word into a position where it is read as a person name.

What changed

Stages that did not run.

A stage is listed here when the captured _explain object contains none of its keys, when a default value switches it off, or when it ran and contributed nothing.

Time decay

time_decay_days defaults to 0.0. time_decay() returns 1.0 whenever that value is at or below zero, so nothing decays with age unless you set it. Every candidate in this capture reports time_decay 1.0.

Cross-encoder rerank

The ms-marco-MiniLM-L-6-v2 model is downloaded by a separate command and was not present. No cross_encoder_score or rerank_blend_alpha key appears in the captured output, so the blend at rerank_blend_alpha 0.5 never happened.

Entity expansion

No entity_expansion, expanded_from_tag or entity_boost key appears in the capture. With three memories, graph enrichment already reached everything an entity tag could have reached.

Hot tier cache

This one is not optional and it is not skipped: every advanced_search queries it first. It holds up to 50 rows with access_count above zero, ordered by access count and refreshed every 300 seconds. mag stats reports total_access_count 0 on this database, so the cache was empty, no _hot_cache key appears in the capture, and there was nothing to merge. When it does return a row, the merge happens after normalisation, which is the one path on which a returned top score is not 1.0.

Keyword-only fast path

Taken only when the intent is Keyword or the query is blank. This query classifies as Conceptual, so the full pipeline ran. The fast path would have skipped embedding, vector search, RRF, cross-encoder, graph enrichment and entity expansion.
