Demo 02 · Handoff

One tool writes.
Another tool asks.

The claim on the front page is that a decision saved by one MCP client can be retrieved by a different one, later, in different words. This is that path, in seven steps, with the row, the tags, the edges and the query output as MAG actually produced them.

Captured 4 September 2026 with mag 0.1.10-dev on its default feature set, against an empty database. Both halves run against the same file, ~/.mag/memory.db. Nothing here goes over a network and no account is involved; the second tool reads the row because it is on the same machine.

Two defects visible in this demo

Every content value starts with processed: . The CLI store path routes through a compatibility pipeline that prepends that string before the row is written, so the stored text is not the text you typed.

The tag entity:people:retries follows from the same bug. The extractor skips the sentence-initial word before looking for capitalised name-like tokens, so the injected prefix shifts the real first word into the position it examines, and Retries is filed as a person. The same run produced entity:people:schema on the third memory.

Neither defect stops retrieval working, and both are shown here rather than cleaned up, because the row on this page is the row in the database.
