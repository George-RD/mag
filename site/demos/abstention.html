Demo 03 · Abstention

The query that
returns nothing.

MAG would rather give an agent an empty array than a plausible wrong memory. That decision has a cost, and this page is the cost. Two queries run against the same three memories. The first works. The second is a reasonable paraphrase of the first, and it comes back empty.

Captured 4 September 2026, mag 0.1.10-dev on its default feature set, bge-small-en-v1.5 int8. Both queries were run with mag advanced-search against the same database, seconds apart.

What changed

Say it plainly.

This is a limitation, not a feature.

The second query is a fair question. A person reading the three memories would answer it from the first one. MAG returns an empty array, and the agent that asked has no way to tell an empty database from a query the gate rejected, because the CLI prints {"results":[]} in both cases.

The reason is that the gate is lexical first. It looks at how many query tokens appear in a candidate, and the paraphrase shares none: policy, request, fails, try and again do not appear in "Retries use exponential backoff with jitter, capped at 30 seconds". The semantic rescue exists for exactly this case, but it is deliberately narrow, and here it does not fire.

Two smaller failures sit behind the visible one. The embedding ranked the schema memory above the retries memory for this paraphrase, so even a purely semantic pipeline would have led with the wrong row. And the stemmer turns request into requ: the word ends in -est, so the -est rule at scoring.rs:461 takes the last three characters off, leaving a fragment that appears nowhere in the corpus.

What the gate buys

On the 100-question local benchmark (data/local_benchmark.json, 80 seeded memories), MAG scores 20 out of 20 in the abstention category against 16 out of 20 for omega-memory on the same 20 questions. Those are questions where the correct answer is that the store does not know. Without a gate, a retrieval system answers all of them wrongly and confidently.

The questions and the seed corpus are held constant; the storage and retrieval code is not. MAG's row comes from cargo run --release --bin longmemeval_bench -- --json, omega-memory's from benches/python_comparison.py against its own SQLite store. Both are recorded at commit 83abccf, 2026-03-28, macOS aarch64, in the benchmark report.

What would change it

Raising recall here means either loosening abstention_min_text below 0.15, which trades abstention accuracy for it, or widening the semantic rescue, which currently requires a single dominant candidate above cosine 0.82. Neither has been measured as a change, so neither is claimed as a fix.
